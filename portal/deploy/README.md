# Веб-портал Nizya

Часть функций бота в браузере: вход по коду из письма, личный кабинет,
покупка тарифов. Отдельный сервис — живёт на своей ВПС и ходит в API бота
(`app/cabinet/`) через туннель WireGuard.

## Почему так

- **Отдельная машина.** Портал смотрит в интернет, бот — нет. Падение или
  взлом портала не роняет бота и не даёт доступа к его базе.
- **Серверный рендер.** Страницы собираются на сервере (Jinja), токены
  пользователя остаются в Redis портала, в браузер уходит только
  идентификатор сессии. Поэтому CORS не нужен вовсе: браузер в API бота не
  ходит.
- **Один набор версий.** Зависимости портала пиннятся теми же версиями, что
  в `pyproject.toml` бота: расходиться им незачем, а тесты портала гоняются
  в том же CI.

## Что нужно поднять

1. **Туннель WireGuard** между машинами. Портал обращается к боту по
   приватному адресу, порт API наружу не открывается. Адрес подставляется в
   `PORTAL_API_BASE_URL`.
2. **Домен** портала в A-записи на его ВПС и в `PORTAL_DOMAIN` — по нему
   Caddy сам выпустит сертификат при первом обращении.
3. **Почта у бота.** Код входа отправляет бот, поэтому SMTP настраивается на
   его стороне (`app/cabinet/services/email_service.py`). Без рабочей почты
   вход по коду не работает: ручка честно отвечает 503.
4. **`CABINET_ENABLED=true`** в `.env` бота — иначе ручек кабинета нет.

## Запуск

```bash
cp .env.example .env     # заполнить адреса и домен
docker compose up -d --build
docker compose logs -f portal
```

Проверка: `curl -s https://<домен>/healthz` → `{"status":"ok"}`.

`/healthz` нарочно не трогает ни Redis, ни бота: это проверка «процесс
поднялся». Иначе падение бота заставляло бы Docker перезапускать портал, хотя
перезапуск ничего не лечит.

## Файлы

| Файл | Зачем |
|---|---|
| `Dockerfile` | образ портала; контекст сборки — корень репозитория, копируется только `portal/` |
| `docker-compose.yml` | портал + его Redis + Caddy |
| `Caddyfile` | TLS, заголовки безопасности, проксирование на портал |
| `requirements.txt` | версии как у бота |
| `.env.example` | шаблон конфига |

## Разработка на своей машине

```bash
PORTAL_COOKIE_SECURE=false PORTAL_API_BASE_URL=http://127.0.0.1:8080 \
  uv run uvicorn portal.main:app --reload
```

`PORTAL_COOKIE_SECURE=false` нужен только тут: по http браузер cookie с
флагом `Secure` не сохранит. На проде флаг включён.

Тесты портала — в `tests/portal/`, гоняются общим `make test`.
