# Наблюдатель доступности бота

Отдельный контейнер рядом с ботом (`remnawave_bot_watchdog`). Раз в минуту
проверяет, может ли человек получить ответ от бота, и при затяжном сбое пишет
тревогу в Telegram **вторым ботом**.

## Что именно он проверяет

| Проверка | Что ловит |
|---|---|
| `GET /health` бота отвечает | процесс умер, перезапускается, завис наглухо |
| `availability.telegram.seconds_since_ok` | путь бот↔Telegram оборвался: процесс жив и бодро отвечает, а апдейты копятся на стороне Telegram |
| `availability.updates.p95_ms` | бот отвечает, но слишком медленно (блокировки базы, тормоза панели) |
| свой запрос к api.telegram.org | чей это сбой: бота или связи с Telegram вообще |

Показатели считает сам бот: канарейка раз в 30 секунд дёргает Telegram **той же
сессией**, что и рабочие запросы (тот же маршрут, прокси и пул соединений —
иначе проверка зелёная, когда боту плохо), а внешняя мидлвара замеряет время
обработки каждого апдейта. Обе величины отдаются в `/health` разделом
`availability` — см. `app/services/availability_monitor.py`.

Почему именно так: 2026-11-20 бот молчал, а `/health` отвечал за 24 мс.
Обычный пинг такой сбой не видит — его видно только по возрасту последнего
успешного контакта с Telegram.

## Чего он не увидит

**Смерть самой ВПС или её сети.** Наблюдатель живёт на той же машине, и в этом
случае молчат оба — тревогу не пришлёт никто. Закрывается только проверкой с
другой машины, на выбор:

- **ВПС портала** (есть туннель): крон раз в минуту, `curl` до
  `http://10.8.0.1:8080/health`, при двух промахах — сообщение тем же вторым
  ботом;
- **внешний dead-man's switch** (healthchecks.io и подобные): наблюдатель или
  бот раз в минуту пингует их URL, сервис сам шлёт в Telegram, когда пинги
  прекратились. Ничего не поднимать, но зависимость от третьей стороны.

Это сознательно не сделано: владелец выбрал размещение на ВПС бота.

## Настройки

Читаются из `.env` бота (тот же файл, контейнер получает его через `env_file`):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WATCHDOG_ALERT_BOT_TOKEN` | — | токен **второго** бота для тревог. Пусто — наблюдатель работает, но молчит |
| `WATCHDOG_ALERT_CHAT_ID` | — | куда писать: ваш id или id админ-чата |
| `WATCHDOG_INTERVAL_SECONDS` | `60` | как часто проверять |
| `WATCHDOG_FAILURES_BEFORE_ALERT` | `3` | сколько плохих проверок подряд до тревоги |
| `WATCHDOG_TELEGRAM_STALE_SECONDS` | `180` | сколько секунд без ответа Telegram считать обрывом |
| `WATCHDOG_SLOW_P95_MS` | `5000` | порог «отвечает медленно» по p95 обработки |
| `WATCHDOG_SLOW_MIN_SAMPLES` | `5` | меньше апдейтов в окне — p95 не считаем, чтобы не тревожить по одному медленному нажатию |
| `WATCHDOG_HEALTH_URL` | `http://bot:8080/health` | адрес бота внутри сети compose |

Второй бот — любой новый бот от @BotFather; **напишите ему `/start` с того
аккаунта или чата, куда ждёте тревоги**, иначе Telegram не даст ему отправить
первое сообщение.

## Запуск и проверка

Контейнер поднимается общим `docker compose up -d` вместе с ботом.

```bash
docker logs -f remnawave_bot_watchdog          # «плохая проверка N: …» и восстановления
docker exec remnawave_bot_watchdog python - <<'EOF'
import json, urllib.request
with urllib.request.urlopen('http://bot:8080/health', timeout=10) as r:
    print(json.dumps(json.load(r)['availability'], ensure_ascii=False, indent=2))
EOF
```

Проверить, что тревоги реально доходят, не дожидаясь сбоя:

```bash
docker stop remnawave_bot      # через 3 минуты должна прийти тревога
docker start remnawave_bot     # затем «снова отвечает» с длительностью простоя
```

## Поведение при инциденте

- тревога уходит после `WATCHDOG_FAILURES_BEFORE_ALERT` плохих проверок подряд
  (единичная заминка не будит ночью);
- про один инцидент пишет **один раз**, не спамит каждую минуту;
- при восстановлении присылает длительность простоя и причину;
- состояние инцидента лежит в томе `watchdog_state`, поэтому перезапуск
  наблюдателя не превращается во вторую тревогу;
- если Telegram недоступен и самому наблюдателю, он так и напишет в тексте —
  это сразу отвечает на вопрос «виноват бот или связь»;
- если тревогу не удалось доставить (Telegram лежит), попытка повторится на
  следующей проверке.
