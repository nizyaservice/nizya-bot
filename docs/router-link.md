# Роутер-ссылка: продажа vless-ключа одной локации

Пользователь платит с баланса и получает `vless://…`-ссылку, чтобы прописать её
в VPN-клиент роутера. Ссылка берётся из его же подписки в Remnawave, поэтому
работает, пока подписка жива, и расходует её трафик.

## Что видит оператор

Админка → **Настройки** → **📶 Роутер**:

| Кнопка | Что задаёт |
|---|---|
| 💰 Стоимость | цена одной локации (ввод в рублях, хранится в копейках) |
| 🧩 Сквад | список внутренних сквадов панели, из которых разрешено продавать |

Услуга продаётся, только когда заданы **и** цена, **и** хотя бы один сквад:
нулевая цена — выключатель, иначе оператор, добавивший сквад и забывший цену,
начал бы раздавать ключи бесплатно. Имя сквада вводится руками и сверяется со
списком панели — опечатка иначе выглядела бы как «функция не работает».

Настройки живут в `system_settings` (`router_link.price_kopeks`,
`router_link.squads`), как и картинки разделов: правятся на ходу, перезапуск
бота не нужен, в `.env` их нет.

## Что видит пользователь

Вход — кнопка **📶 Ссылка для роутера** во вкладке «Моя подписка» (видна, когда
услуга настроена и подписка не пробная). Дальше:

1. список доступных локаций с ценой;
2. подтверждение: локация, сумма, баланс до и после;
3. списание с баланса — и только теперь экран с ключом.

Оплаченная локация остаётся доступной: повторный показ бесплатный, помечен
галочкой в списке. Другая локация — отдельная оплата.

## Какие локации доступны

Цепочка фильтров (`app/services/router_link_service.py`):

```
сквады, включённые оператором
  ∩ сквады, в которых состоит пользователь (панель, activeInternalSquads)
  → хосты этих сквадов: инбаунд хоста ∈ инбаунды сквада,
    host.internalSquads: ALLOW_ONLY → сквад в списке, EXCLUDE → не в списке,
    isHidden/isDisabled — пропускаем
  → ссылка подписки, у которой `#remark` совпадает с remark хоста
    (при переименовании хоста — сверка по адресу и порту)
```

Так ключ не может прийти из сквада, который оператор не включал, или из
сквада, в котором пользователя нет. Для текущей конфигурации это `game-premium`
и `game-standart`.

## Почему ссылку нельзя снять до оплаты

Требование владельца: ключ не должен утекать ни в сообщение, ни в трафик бота
до оплаты. Как это обеспечено:

- до списания бот **не запрашивает** ключи подписки у панели вовсе — запрос
  идёт после успешного `subtract_user_balance` (и при повторном показе уже
  оплаченной локации). Перехватывать нечего: ключа ещё никто не получал;
- до оплаты наружу уходит только имя локации; адрес, порт и SNI остаются внутри
  сервиса, в `callback_data` ездит лишь UUID хоста;
- доступность пересчитывается по панели при каждом шаге, а не берётся из
  `callback_data`: устаревшая кнопка чужого сквада ничего не продаст;
- ссылка не хранится в нашей базе (таблица `router_link_purchases` хранит право,
  а не ключ) и не пишется в логи.

Списание и запись права уходят одним коммитом под блокировкой строки
пользователя — двойной тап по кнопке не спишет деньги дважды (плюс уникальное
ограничение `(user_id, host_uuid)`).

Если панель не отдала ключ сразу после оплаты, право всё равно записано:
пользователь видит «доступ оплачен, ссылка появится» и получает её при
следующем открытии экрана.

## Где что лежит

| Файл | Роль |
|---|---|
| `app/services/router_link_service.py` | настройки, выборка локаций, сопоставление ссылки, покупка |
| `app/handlers/router_link.py` | экраны пользователя (`router_link`, `router_link_buy/pay/show:{host}`) |
| `app/handlers/admin/router_link.py` | админский экран (`admin_router_link`) |
| `app/database/crud/router_link.py` + модель `RouterLinkPurchase` | учёт оплаченных локаций |
| `migrations/alembic/versions/0133_router_link_purchases.py` | таблица |
| `tests/services/test_router_link.py`, `tests/handlers/test_router_link_screens.py` | выборка локаций, порядок «оплата → ключ», отсутствие ключа на экранах до оплаты |
